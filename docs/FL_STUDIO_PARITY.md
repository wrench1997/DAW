# Citrus Studio development - FL-class capability matrix

This document tracks clean-room implementation progress. "FL-class" means a long-term target of comparable production capability and a familiar pattern-first workflow. It does not mean copying FL Studio branding, source code, artwork, bundled content, project data, or pixel geometry, and it does not mean that parity has already been achieved.

Status terms:

- **Working**: implemented and connected for the stated scope
- **Partial**: a useful vertical slice works, but the commercial acceptance target is not met
- **In progress**: core pieces exist, but end-to-end behavior is not connected or verified
- **Not implemented**: no usable product path exists yet

## Important scope notes

### PAT/SONG playback

The transport panel exposes separate PAT and SONG states and plain `L` switches them. PAT constructs a private playback Project containing exactly one synthetic placement of the currently selected Pattern; Playlist Pattern placements, audio clips, automation clips, and automation lanes are excluded without mutating the saved Project or its undo history. Selecting another Pattern requests an immediate Timeline replacement. The PAT loop is derived from the Channel Rack/Piano Roll content and rounded up to a complete four-beat bar, with four beats as the empty-pattern minimum. The Timeline compiler also expands the historical sixteen-beat Piano Roll period when a longer score is placed in a sufficiently long SONG Pattern Clip, so resizing notes beyond beat 16 is not merely visual.

SONG retains the full Playlist compilation path. Left-clicking PAT or SONG selects the mode, right-clicking PAT opens the Channel Rack, right-clicking SONG opens the Playlist, and the mode is stored in `eframe` preferences rather than `.citrus` music data. `Space` toggles play/pause at the current position in this product and `Escape` stops and returns to zero. A PAT/SONG change is rejected while audio or MIDI recording is active because the current MIDI-take implementation still freezes one exact Timeline context and commits a new Pattern plus one Playlist clip; FL-style Pattern-mode overdub/recording semantics remain an explicit gap.

### Playlist grouping and Slip Edit

The Playlist exposes the familiar `P`/`B`/`D`/`T`/`C`/`S`/`E` tool keys for Draw, Paint, Delete, Mute, Slice, Slip Edit, and Select. Select supports Shift-add, Ctrl-toggle, and drag-marquee selection. `Shift+G` assigns a new stable nonzero Clip-group identity to at least two selected Clips, `Alt+G` removes it, and the shared grouping switch temporarily suspends linked behavior without destroying persisted identities. With grouping enabled, click selection and marquee expansion include every member; move, right-edge resize, mute, delete, and duplicate operate on the selected group while preserving relative Clip layout. A complete drag is committed as one Project-history transaction.

Slip Edit changes source content while leaving every Clip `start` and `length` unchanged. Dragging right moves source content left; Playlist snap applies unless `Alt` is held. Pattern offsets wrap through the Pattern content period and feed both the callback Timeline compiler and the PCM24 arrangement exporter. Audio offsets are clamped in native asset frames after accounting for the visible Clip duration and TempoMap. Automation offsets are bounded to the lane source range. Pattern ticks, Audio waveform windows, and Automation curves are drawn from the resulting source position. This is a connected Slip core, not time-stretch, warp, ripple, consolidation, or Audio Track support.

Audio Clip fade handles and `create_audio_crossfade` are already connected to Playlist UI. The crossfade requires exactly two same-track Audio Clips with a strict, non-nested overlap and sets the overlap-length fade-out/fade-in while preserving opposite fades. Realtime and offline Audio Clip paths use the shared equal-power envelope. This narrow feature still needs real-media/UI validation and does not imply a full sample editor.

### Piano Roll scale and Chord Stamp

The manual helper row stores its root, scale/mode, shading, pitch-constraint, chord preset, and `ONLY ONE` values in versioned `eframe` editor preferences, independently of `.citrus` Project music data. Shading distinguishes root, in-scale, and out-of-scale key rows. Pitch constraint is intentionally edit-scoped: newly drawn notes, chord previews/placements, canvas moves, and Inspector pitch/time moves are mapped to the nearest selected-scale pitch with deterministic downward tie-breaking, while untouched out-of-scale notes are not rewritten. Alt bypasses canvas snapping. It does not currently rewrite imported notes, recorded/live MIDI, resize/velocity-only edits, or existing notes merely because the preference changed.

Chord Stamp uses one click at the snapped grid time and root row to build the selected interval preset in the active target Channel. The complete candidate allocates stable IDs, suppresses only exact same-Channel/pitch/start duplicates, previews and auditions every inserted note, and commits as at most one undo transaction; `ONLY ONE` returns to Draw only after a successful insertion. This is a manual built-in subset of the referenced workflow, not support for FL Studio `.fsc` score files, user-defined Stamp banks, or automatic scale analysis.

### Piano Roll Articulate and Arpeggiate

`Ctrl+L` applies the built-in Legato articulation directly to selected target-Channel notes, or all target-Channel notes when there is no applicable selection. `Alt+L` opens a realtime Articulate preview with Legato, Portato, Staccato, Small gap, and Chop chords presets; length multiplication, deterministic seeded variation, existing-length/chord-chop behavior, and selected-only boundary lookup are explicit. `Alt+A` opens the built-in Arpeggiate preview with four deterministic directions, one-to-four-octave expansion bounded to MIDI 0..127, grid/time multiplier, Time/Block/Chord end synchronization, gate, stable source-ID reuse plus bounded allocation, and optional fresh note grouping. Cancel restores both project and selection exactly; Accept and Quick legato each commit at most one history transaction. This does not claim FL `.fsc` score-pattern import, per-level modulation, or every proprietary preset.

### Audio device profiles and controlled restart

Output and input settings use serializable profiles whose stable identity includes both the CPAL host ID and device ID, avoiding display-name matching when two devices share a name. Sample rate and channel count offer deterministic `Default`/`Exact`/`Nearest` selection, sample format offers default/exact/automatic selection, and buffer size offers backend-default/fixed/nearest selection. Settings exposes the requested profile separately from the effective stream configuration and the actual callback observations; callback frame counts, timing, and stream-fault state are observations rather than inferred nominal settings. These preferences live in versioned `eframe` storage and are not serialized into a `.citrus` Project.

An output change follows a controlled restart design: prepare and warm a candidate while retaining the current engine, preserve the session state needed for restoration, and try requested, last-known-good, then system-default profiles. The path is deliberately described as controlled restart rather than seamless hot-swap. Final integration and adverse failure-path validation are still in progress, and physical unplug/replug, unusual callback partitions, sleep/resume, long-running streams, and a varied hardware/driver corpus still need sustained testing. Audio recording resolves the selected input profile when a take starts. On Windows, the current CPAL default is WASAPI; this build does not enable ASIO.

### VST realtime graph

Each active Mixer insert is one worker containing its complete physical-slot order. Each VST Channel generator is a separate one-slot worker. A fixed 128-frame adapter accumulates arbitrary supported device callback partitions and exchanges planar stereo blocks through bounded SPSC queues; the callback never executes a vendor DLL, allocates ordinary working buffers, waits on a lock, or destroys an endpoint. The callback renders the validated MainInput DAG in topological order: PreEffects sends, the source Insert, PostEffects sends, mute/solo/fader/pan, then PostFader sends. Master runtime slot 0 is the sole output sink, and there is no implicit all-tracks-to-Master sum outside the compiled routes.

The adapter has one 128-frame input-accumulation quantum plus one 128-frame asynchronous bridge quantum before reported plug-in latency. MIDI and bounded realtime events retain offsets inside that quantum. Each endpoint reserves independent, non-borrowing System/Timeline/Live event quotas: 16/96/16 events per 128-frame quantum and 16/224/16 per device callback. Overflow, stale/mismatched output, invalid events, and incomplete delayed-dry cases are diagnosed and fail closed instead of substituting audio from another sequence. Endpoint replacement is not considered active until the audio callback confirms it, and the old worker guard remains alive until its retired endpoint has returned to the control thread.

Graph PDC is implemented for the bounded MainInput DAG. A fixed-capacity plan aligns raw sources, Generator workers, Insert stages, and every active route at each join from coherent endpoint latency snapshots. Active route delay is held in a sparse prepared bank; graph identity, route identity, endpoint manifest, active-slot mask, PDC revision, or worker latency-revision drift rejects or silences the candidate and requests resynchronization. Dynamic retiming is preflighted before the bank target changes. Sidechain/multi-output buses, hardware/input latency, recording alignment, and plug-in-aware offline equivalence remain unsupported.

VST3 uses the packaged `vst3-host-helper` process. VST2 executes on a dedicated worker thread but remains inside the application process: a hung call is detached so the UI need not wait, while a native access violation can still terminate the application. Rust cannot safely kill an arbitrary stuck in-process plug-in thread. A commercial build therefore still needs VST2 process isolation or an equivalent sacrificial-host design.

Project v10 persists Playlist Clip-group identities while retaining the pattern-local Piano note groups introduced in v9 and the stable Timeline, Mixer-track, Mixer-route, and plug-in identities introduced through v8. Mixer display order is independent of fixed callback runtime slots, while channel, Clip, automation, placement, route, note-group, and Clip-group references use stable IDs. Older projects migrate deterministically; v9 Clips and v8 notes without group fields load ungrouped, singleton or zero group identities normalize away, and malformed v8 Mixer IDs, placements, slots, or routes are rejected instead of silently normalized away. Runtime availability is session-only. Base parameters are replayed when a slot becomes ready. Manual save and autosave first wait for every admitted generic parameter edit to reach a terminal worker receipt, then wait for pending callback-confirmed graph changes before issuing generation-tagged state requests to the exact running endpoint/slot identity. A bounded parameter-edit timeout fails those edits and aborts that save attempt instead of persisting speculative UI values. Transient full control queues are retried. Topology and state capture each receive a bounded one-second phase: an unconfirmed topology aborts the save, while unresolved state is explicitly reported and the last confirmed state is used. Only then does synchronized same-directory atomic project replacement occur; an unrelated older state event cannot satisfy the barrier. A manual save containing stale plug-in state updates the target file but deliberately remains marked unsaved. Exit without a completed barrier can only retain the most recently confirmed state.

Identified workers also carry a fixed-size, creation-time physical-slot manifest with nonzero unique instance IDs. Audio and control endpoint owners receive the same immutable copy, while legacy constructors expose unknown identities rather than fabricating them. Callback plug-in automation consumes the manifest when the compiled route and installed endpoint identify either the same one-slot Generator/slot 0 or the complete dense physical order of an ordinary Mixer Insert 1..31. It binds a coherent latency revision and active-slot mask; endpoint, manifest, PDC-plan, latency-revision, or active-slot drift fails closed and requires Timeline resynchronization instead of continuing against stale control timing. For Mixer Inserts, each target's Q128 value comes from transactional history delayed by the raw-source PDC amount plus the latency prefix before its physical slot. Master Insert 0 and multi-slot Generators remain outside this path. A generic catalog captures an immutable bounded snapshot per request, returns at most 64 descriptors per page, and accepts pages only from the exact project session, endpoint, instance, runtime slot, request, cursor, and catalog revision. Opening or filtering it never changes the Project; the explicit automation action creates or opens the corresponding lane.

Eligible catalog parameters also expose reliable normalized sliders. A submission remains a retryable Draft until the audio command is admitted; repeated A/B/C movement keeps one in-flight target and coalesces the successor to the latest C value. Exact callback rejection and dedicated worker `Applied`/`Failed` receipts are terminal outcomes. The Project base parameter is committed only from the final worker `Applied` value, never from a draft, callback acceptance, readback, or failed edit. A parameter currently owned by compiled Timeline automation remains read-only in this editor. Vendor editors, MIDI learn, gesture begin/end with grouped undo, automation recording, and touch/latch/write modes remain absent, so this is not yet a complete preset/editing product.

### MIDI scheduling

Compiled Step and Piano Roll events use the Timeline's authoritative frame/epoch cursor on the audio callback. Note-on/off ordering and stable occurrence IDs are preserved, discontinuity chase can restore active notes, and events for worker-backed generators retain sample offsets through fixed-quantum accumulation. Pause, stop, loop, route changes, generator replacement, and project changes clear or re-chase callback-owned note state.

UI audition, hardware live MIDI, and the legacy command fallback are not the compiled Timeline path and do not provide one universal sample-accurate contract. The narrow hardware-input route does preserve its mapped sample offsets while transport is playing, subject to fixed-quantum worker delivery and the Generator's Live-event quota, but individual vendor MIDI events still have no end-to-end acknowledgement. Do not generalize the compiled-song guarantee to every live or compatibility path.

On Windows, `midir` 0.11 uses its WinMM backend for stable port enumeration, periodic hot-plug refresh, and control-thread connection ownership. The current product path owns exactly one selected input and binds its dedicated bounded SPSC receiver to exactly one callback-confirmed one-slot Generator. Its route stamp carries the project session, Channel, endpoint, plug-in instance, and physical slot identity. Installation, removal, and clear use exact callback receipts; replacement, disconnect, destination drift, hot-unplug, transport-epoch change, or input overload triggers destination-specific CC123/all-notes-off safety, and the receiver is retired back to the control thread instead of being destroyed in the callback.

The first valid event anchors that connection's backend timestamp to the current audio-device frame. Later events use saturating integer timestamp deltas: events mapped behind the callback clamp to its first frame, while future events remain pending for a later callback. While playing, accepted channel messages retain the resulting in-callback sample offsets and enter the exact Generator's bounded Live lane without borrowing its System or Timeline quota. While paused, monitoring audibly advances only the target Generator and its compiled downstream Mixer-DAG closure through Master; the Timeline cursor, native/audio voices, unrelated Generators, non-downstream Inserts, and unrelated PDC histories stay frozen.

The exact live route has one narrow recording path. Recording starts only after the callback confirms a playing, Timeline-ready boundary for the same project, route, endpoint, instance, revision, transport epoch, and connection epoch. Only Note On/Off edges that successfully entered the Generator's Live lane are mirrored to a separate bounded recording SPSC, with their mapped device frame and authoritative Timeline frame. Paused monitoring is never captured. Stop is callback-confirmed; the control side drains all prior edges, pairs overlapping notes FIFO-style, closes held notes at the exact stop boundary, and converts each edge independently through the frozen TempoMap. A valid take atomically creates a new Pattern and exactly one Playlist Pattern clip and is one undo step; an empty or invalid take changes neither the Project nor history.

That recording path is intentionally limited to one non-looping 16-beat legacy Piano period. Any loop/epoch, route, project/source, timestamp, overload, or frozen-context drift invalidates the whole take. It does not record CC, sustain pedal, pitch bend, channel pressure, poly pressure, MPE, SysEx, or clock, and it has no overdub, punch, take-lane, comping, input-latency calibration, or simultaneous audio+MIDI workflow. Physical-device stress and long-run input/audio-clock drift calibration remain outstanding, as do multiple simultaneous inputs, multiple destinations, native-Channel routing, and controller learn/mapping. MIDI output is still a separate bounded worker that sends promptly; it has no audio-render integration or sample-clock deadline scheduler.

### Timeline activation

The callback is authoritative for Timeline frame, epoch, loop boundaries, and playing state. A control request packages revision, chase frame/beat, loop range/token, playing state, epoch constraints, fixed Mixer layout, graph-PDC plan, sparse delay-bank ownership, and endpoint-latency identity into one activation. The callback preflights every candidate resource and retirement slot before committing. Same-graph replacements may reuse the exact active bank only after fingerprint verification. It publishes one exact receipt only after the in-callback commit; a rejected replacement leaves the current Timeline, graph, bank cursors, transport, voices, automation, and PDC history intact.

### Automation

The project stores typed lanes and editable points. The Timeline compiler resolves precedence and emits typed base/chase state, ramps, and exact layer-end transitions. On the callback, the typed executor separates discontinuity chase values, in-block transitions (`before`, `after`, and carried shape), and exclusive block endpoints. A fixed-capacity transactional kernel renders linear/hold values per sample and commits its value/shape cursor only if the complete audio block and downstream binding checks succeed.

Kernel coverage does not imply that every target changes DSP. The connected paths are deliberately narrow. `ChannelVolume`, `ChannelPan`, and `ChannelMute` are consumed sample-exactly for an internal/native Channel only when no compiled Generator route exists, and are applied while producing the raw source, before source PDC. Separately, exact-manifest plug-in endpoints can consume `PluginParameter` values at each 128-frame quantum boundary for a one-slot Generator's physical slot 0 and for active slots of ordinary Mixer Inserts 1..31. These Q128/block-rate routes are invariant to supported device-callback splitting and place parameter updates before Timeline MIDI at the same boundary; they are not sample-exact automation.

Generator-backed application of the native Channel targets, Master Insert 0 and multi-slot Generator `PluginParameter` routes, and the Master, Mixer-control, `Tempo`, and `Swing` target families remain unsupported by the callback and are counted in pending/unsupported diagnostics. The older application evaluator still dispatches several Master/Mixer/Channel/tempo/swing/plug-in values at UI rate; this compatibility behavior is not sample-accurate and is not evidence that those pending callback targets are connected. Generic manual slider edits use an exact callback-plus-worker receipt path and commit Project state only on final worker `Applied`; compiled Timeline-owned parameters remain locked against competing manual edits. MIDI learn, gesture begin/end with grouped undo, automation recording, touch/latch/write modes, and a defined smoothing policy remain absent.

### Audio Clips and recording

WAV assets use a strict bounded decoder and an acknowledged callback asset table. Playlist play/sync/stop honors source offset, normalized fades, source/output sample-rate stepping, and Mixer routing. It is not a stretch, warp, transient, or pitch engine.

Recording resolves the selected host-aware input profile when a take starts. The callback pushes complete interleaved frames to a bounded SPSC queue, while a background writer emits fixed 64 KiB PCM24 blocks into a same-directory temporary file, drains and synchronizes it, then publishes without clobbering an existing target. The callback ring is capped at 32 MiB and a take is capped at 134,217,728 interleaved samples (about 23.3 minutes at 48 kHz stereo). There is no track arm/monitor/input-routing, calibrated latency, punch/loop capture, take lane, or comping workflow.

MIDI note recording is separate from that audio-input writer. It records only callback-accepted Note On/Off edges from the active exact Generator route, commits a complete take as a fresh Pattern and one Playlist placement, and leaves the Project untouched on any invalidation. Realtime and offline legacy Piano playback both use a 16-beat repeat period, preventing the exporter from introducing shorter accidental repetitions for these takes.

### Export

The PCM24 exporter follows Playlist Pattern/WAV placement, repetition, source offset, gain, fades, and resampling, then evaluates the same compiled plugin-free MainInput DAG semantics for chain/fan-out/diamond routing, taps, route gain, track/master controls, mute, and solo closure. Encoding is buffered and committed through a synchronized same-directory temporary file. It remains a separate whole-song renderer and does not run VST instruments/effects, plug-in automation, tails, graph PDC, stems, freeze, or dithering choices. Active plug-in placements or sidechain routes block export rather than being silently omitted.

### Realtime Master Capture

The live Master tap in `audio.rs` and File-menu/diagnostics controls in `app.rs` connect to `master_capture.rs`. Capture uses callback-confirmed lifecycle events, a bounded preallocated SPSC, device-frame sequence tracking and a background PCM24 WAV writer with synchronized no-clobber publication. Missing/overflowed frames become explicit silence and invalid metadata rather than silently shortening the recording. It records the output the realtime graph actually produces, including live plugin output, but does not establish deterministic offline plugin rendering, tails, stems or offline graph equivalence. Current-session hardware validation is pending.
