# Native sampler (project format 15)

Each Channel can own one WAV sampler, saved as optional `sampler`. `sampler: null` (or absent) means the existing native oscillator. `sampler: { asset_id: null, ... }` is an explicitly empty, silent sampler, retained after cancelling Load or removing the sample; it never falls back to an oscillator. `asset_id: <number>` selects a source; a missing numbered source is an error, not an empty slot. Format 15 prevents older format-14 builds silently interpreting sampler notes as oscillator notes. Sampler and VST generator assignments are mutually exclusive in saved projects; defensively, compiled VST assignments take precedence. The editor must complete its normal timeline/asset publication barrier before auditioning changed settings.

`SamplerConfig::new(asset_id)` selects the entire asset with MIDI root 60. `SamplerConfig::empty()` makes an empty sampler. Empty slots persist through save/reopen, require no audio asset, and neither emit sound nor block other channels or offline export. Previous numeric `asset_id` JSON remains readable; null source IDs make earlier builds expecting a numeric field reject the configuration instead of silently rendering an oscillator. Start is inclusive; end is exclusive; all positions are native source frames. End `None` means the source end. Optional loop start/end must both be present and lie within the trim region. ADSR defaults: 5 ms attack, 50 ms decay, sustain 0.8, 100 ms release. Durations must be finite in 0–60 seconds, sustain 0–1. Invalid settings fail closed; missing media never selects an oscillator. A missing catalog entry remains repairable on project open; transport/media preparation reports the missing asset and offline export fails explicitly.

Playback is linear-interpolated, rate-changing resampling: `source_rate / device_rate * 2^((note-root)/12)`. It is not time stretching. Mono duplicates to stereo; stereo stays stereo. A loop repeats through the release stage, which linearly fades from the current attack/decay/sustain level. Note-off triggers release; source exhaustion stops a non-looping voice even if the key remains held. No implicit normalization or oscillator attenuation is applied to PCM. Channel/clip gain, pan, mixer routing and existing automation remain external.

Realtime and offline use the same allocation-free `SamplerVoice`. Realtime occupies the existing bounded native voice pool and references existing registered immutable PCM slots; no WAV decode or new sample buffer occurs in the callback. Missing/invalid registrations reject sample starts. Asset replacement, unregister, clear, transport reset and all-notes-off stop the associated voices. Timeline chase restores the held note's source position and ADSR age. At note-off the release drains; stopping/seek use existing hard-reset semantics. Asset retirement keeps final PCM destruction off the callback.

Piano-key audition and Pattern/Song notes use this path; offline WAV export decodes native-rate media once, applies note durations, and renders releases into the configured tail. Physical MIDI input currently targets the existing VST generator route; native sampler device-input routing has not been added or accepted in this change.

Sampler assets live in `Project.audio_assets`, so project media inspection, explicit relocation, and save/reopen reuse the existing media pipeline. Saving persists the source reference; it does not embed or package the WAV. Explicit Locate resolves a replacement to an absolute path. Existing relative references retain their existing path semantics. `CompiledTimeline::sampler_asset_ids()` includes sampler-only channels with no scheduled notes to keep audition media registered. Runtime readiness uses the same stable project-ID registration invariant as Audio Clips.

Tests cover deterministic PCM, octave/rate ratio, stereo, interpolation, ADSR release, loop wrapping, invalid ranges, non-finite input, idempotent chase, serialization, callback allocation guard, missing assets and unregister. Export tests render real WAV fixtures. Device/speaker listening and Windows GUI acceptance are separate from these deterministic tests.
